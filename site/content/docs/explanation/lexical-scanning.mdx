---
title: Why every rule is lexical
description: No parser, no type resolution — what that buys, and what it costs.
---

Every rule in Straitjacket is **lexical**. It reads files and applies patterns.
It does not build a syntax tree, resolve types, or follow a call from one file
into another. That is a deliberate constraint, and it is the single decision
that most shapes what the tool is good at.

## What it buys

**It runs on anything, with no setup.** There is no project to configure, no
`tsconfig` to find, no toolchain to install, no dependency graph to resolve
first. Point the binary at a directory and it produces findings. A scanner that
needs your build to work cannot run on the repository that is currently broken,
which is often exactly when you want it.

**It is language-agnostic by default.** `emoji` does not care whether it is
reading Rust, Markdown or a shell script. `deep-nesting` reads depth off leading
indentation, which is canonical in any language once a formatter is enforced. A
rule written once applies everywhere, instead of once per language grammar.

**It is fast, and the speed is not conditional.** There is no parse step whose
cost grows with the complexity of what it is reading. A scan of a mid-sized
repository finishes in tens of milliseconds, so it fits in a pre-commit hook
without anyone deciding to skip it.

**It is deterministic and explainable.** Every finding points at a byte range
that matched. There is no inference to disagree with — you can see exactly what
tripped the rule, which is what makes the suppression markers a fair escape
hatch rather than an argument.

## What it costs

A lexical scanner cannot tell context from content. It does not know that a
`#ff6600` is inside a comment explaining what not to do, or that a `💖` is a test
fixture deliberately exercising Unicode handling, or that an indented block is
inside a template literal rather than nested control flow.

These are not bugs to be patched one at a time. Reliably answering "am I inside a
string literal?" requires a per-language parser — precisely the thing the design
gives up in order to get everything above. So the false positives are a known,
bounded cost, and the escape hatch is the answer to them:

```rust
// straitjacket-allow-file:emoji — these fixtures test Unicode handling
```

The `unused-marker` rule exists to keep that hatch honest. A marker that stops
suppressing anything — because the code moved, or the rule changed — is itself
reported, so suppressions decay visibly instead of silently accumulating into a
repository nobody is really scanning any more.

## Where the line sits

The rules Straitjacket ships are the ones that survive this constraint: things
that are *visible in the text*. Emoji, color literals, font stacks, inline SVG,
ad-hoc motion, file length, indentation depth, deferred-work markers. Each is a
surface property, and each is a reliable tell.

Rules that need real program understanding — does this value flow into that
component, is this clone semantically the same as that one — are not a lexical
scanner's job, and asking one to do it produces a tool that is confidently wrong
in ways you cannot audit. Straitjacket would rather do less and be checkable.
